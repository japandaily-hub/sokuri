## 設計上の判断（後で崩さないための記録）

1. **直列実行（`workers: 1` / `fullyParallel: false`）**
   シナリオが同じ使い捨て DB の成約・取引を消費する（完了確定・強制終了）。並列化すると
   別テストが掴んだ取引を横取りして偽陽性・偽陰性の双方が出るため、意図的に直列。

2. **案件の新規作成は最後の手段**
   `POST /cases` は AI 解析を伴い、レート上限が **IP 軸・アカウント軸とも既定 10 件/時**
   （`rl_case_create_ip_max` / `rl_case_create_account_max`）。desktop + mobile の 2 周を
   流すと素朴に作ると上限に当たるため、`fixtures.ts` は
   「既存の入札付き open 案件 → 入札の無い open 案件へ入札 → 新規作成」の順で引き当てる。
   シードの 3 案件から始めれば 2 周で新規作成は 1 件程度に収まる想定。
   繰り返し流す場合は `e2e_local.db` を作り直すか、`RL_CASE_CREATE_*_MAX` を上げる（`docs/ops/e2e.md`）。

3. **429 テストの口座は `pending@example.com` 固定**
   ログイン失敗はアカウント軸 5 回/15 分（`rl_login_account_max`）。`seller`/`vendor` を使うと
   同一実行内の後続テストが軒並みログインできなくなる。1〜5 回目は API 直叩きで失敗を積み、
   6 回目だけ `/operator/login` の画面から行って **429 専用の文言**
   （「短時間に試行が集中しました」）が出ること＝「パスワードが違います」に潰されていないことを見る。

4. **`data-testid` は追加しない**
   `getByRole` と表示文言のみ。`getByRole(..., { name })` は既定が部分一致のため、
   「送信」「承認する」のように他ボタンの部分文字列になる名前は `exact: true` を明示している
   （例: チャットの「送信」と「候補日を送信する」）。

5. **モバイルは幅だけ 375px**
   `devices["Desktop Chrome"]` + `viewport 375x812`。タッチエミュレーションを入れると
   hover 前提の導線が本筋と無関係に落ちるため採用しない。

6. **アプリの API クライアントを import しない**
   `web/src/lib/katadzuke-api.ts` は `"use client"` 側の依存を持つ。E2E からは
   `e2e/helpers/api.ts` に必要な型だけ再定義した（型が食い違ったらバックエンドが正）。

## 未検証・リスク（リーダーが実行して確認すること）

- **実行は未実施**（バックエンド・フロント未起動）。`--list` と型チェックまでが本タスクの範囲。
- 画面文言・DOM 構造に依存する箇所で初回失敗が出る可能性があるもの:
  - `/schedule` のカレンダー日付ボタン（「次の月」→ `15` を role=button で選択）。
  - `/admin/operator-applications` の詳細モーダルが会社名を含むこと（`getByRole("dialog")` の絞り込みに使用）。
  - `/admin/contacts` の既定絞り込みが「未対応」で、投入直後の行が一覧に出ること。
  - `POST /operator-applications` / `POST /contact` のペイロード（`category: "service"`、
    `business_type: "corp"`、`account_type: "ordinary"`、許可番号は数字のみ）。バリデーション差異があれば 422 で即失敗する。
  - `01-public-pages` の console error 0 件。ネットワーク由来（`Failed to load resource` / `net::ERR_` / favicon）は
    除外済みだが、開発サーバー特有の警告が error レベルで出る場合は除外リストの調整が要る。
- 公開ページ 8 本は `/`, `/business`, `/examples`, `/faq`, `/vendors`, `/company`, `/terms`, `/privacy` を選定。
  `/condition`, `/photo-guide`, `/legal`, `/contact` は未カバー（必要なら `PUBLIC_PAGES` に足すだけ）。
