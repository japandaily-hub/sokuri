### 4. 通知チャネルの案内が「メール」と「LINE」でページ間に矛盾があり、LINE未連携ユーザーが見落とすリスク
- ルート: `/cases/[id]`（編集対象外）／`/create/complete`／`/chat/[id]`／`/schedule`／`/mypage`
- 該当: `web/src/app/cases/[id]/page.tsx:319,534`（編集対象外）「業者から入札が届くと**メール**でお知らせします」／対して `web/src/app/create/complete/page.tsx:125`「入札が届くと**LINE**に通知が届きます」、`web/src/app/chat/[id]/page.tsx:360`「新着メッセージは**LINEにも**通知されます」、`web/src/app/schedule/page.tsx:538`「**LINE**にも通知が届きます」、`web/src/app/mypage/page.tsx:340-347`「入札・メッセージの通知は**LINEで**受け取れます」
- 問題: バックエンド実装 (`backend/app/services/notify.py`) 上、入札受領等の通知は Brevo 経由の**メール送信が既定**で、LINE通知は `/notifications` で明示的にパスワード確認の上リンクする**任意のオプトイン機能**（`notifications/page.tsx:14-27` のコメント参照）。にもかかわらず出品完了直後の `/create/complete` や交渉中の `/chat/[id]`・`/schedule` は「LINEに通知が届きます」と、あたかも自動的にLINE通知が来るかのように断定している。LINE未連携のユーザー（大多数）はこの文言を信じてメール確認を怠り、入札や日程確定の連絡を見逃す可能性がある。
- 修正案: LINE未連携のユーザーには「メールでお知らせします。LINEでも受け取るには連携してください→」のように条件分岐した文言にするか、最低限「メールおよび、連携済みの場合はLINEでも」という補足を全箇所で統一する。
