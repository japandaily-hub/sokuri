## CSS レベルの具体的修正案（影響の大きい順・8件）

> セレクタ名は screenshot からの推定を含む。`[推測]` と付した箇所は実ファイルでの確認が必要。

### 1. `d_faq` の巨大な黒円を殺す（最優先・単独で1→3に戻る）

黒くなっているのは装飾ブロブの塗りが**未定義のカスタムプロパティにフォールバックを持たせていない**ため。`background: var(--kz-blob)` が invalid になると初期値（`transparent`）ではなく、SVG の `fill` 経由の場合 `currentColor`＝黒に落ちる。

```css
/* [推測] web/src/app/faq/faq.css */
.faq-hero::before,
.faq-hero__blob,
.faq-hero svg circle {
  /* 変数名の綴り違い・未定義に耐えるよう必ずフォールバックを持たせる */
  background: var(--kz-blob, #EEF3E6);
  fill: var(--kz-blob, #EEF3E6) !important;
}
/* 保険: この面に黒塗りの円が出ること自体を禁止 */
.faq-hero svg [fill="currentColor"] { fill: #EEF3E6; }
```

加えて、`⚙ ¥ ⊙ ✧ ◎` がテキストとして露出している件はアイコンコンポーネントの読み込み失敗。CSS 側の応急処置は

```css
.faq-cat__icon, .faq-chip__icon { display: none; }   /* グリフ露出を止める */
.faq-chip { display: inline-flex; align-items: center; gap: .5em;
            padding: 6px 14px; border: 1px solid #DDE3D6; border-radius: 2px;
            font-size: 13px; letter-spacing: .04em; }
```

を当て、根治は当該コンポーネントの import 復旧で行う。**CSS だけで閉じる問題ではない点を明記する。**

### 2. `d_examples` の約1,800px空白を潰す

カードが0件描画。CSS でできるのは「空でも壊れて見えない」ようにすることだけ。

```css
/* [推測] web/src/app/examples/examples.css */
.examples-grid:empty { display: none; }
.examples-section { min-height: 0; padding-block: clamp(48px, 6vw, 96px); }
.examples-grid:empty + .examples-empty { display: block; }  /* 空状態の文言を出す */
```

根治はデータ／レンダリング側。**この画面は「余白過多」ではなく「欠落」なので、デザイン修正では合格に持ち込めない。**

### 3. 緑を2種に絞り、LINE緑を「LINE導線だけ」に隔離する

現状、LINE緑 `#06C755`（高彩度）が主CTA・ヘッダCTA・モバイル固定バー・お問い合わせパネルに散っており、モス緑 `#4A6B3E` 系と2系統が同一スクロール内で衝突している。

```css
:root {
  --kz-green-brand: #4A6B3E;   /* 人の森寄りのモス。サイト既定のCTA色 */
  --kz-green-line:  #06C755;   /* LINE公式色。LINEに遷移するボタンにのみ許可 */
}
/* 既定CTAはブランド緑に統一 */
.btn-primary, .cta__primary, .site-header__cta {
  background: var(--kz-green-brand);
  border-radius: 2px;          /* 人の森は角丸をほぼ使わない */
  font-weight: 500;
  letter-spacing: .04em;
}
/* LINE緑は「LINEアイコンを伴うボタン」だけに限定 */
.btn-line { background: var(--kz-green-line); border-radius: 2px; }
```

第一画面のヘッダCTAは LINE 導線なので LINE 緑を残してよいが、**面積を減らす**（高さ 44px、左右 padding 20px 程度）と人の森のトーンに収まる。

### 4. 青の除去（bundle の3Dイラスト＋flow の人物写真）

サイト内最大の色破断。差し替えが本筋だが、CSS で即応するなら:

```css
/* まとめ売り節の3Dレンダー: 青を緑側へ寄せて彩度を落とす */
.bundle__figure img {
  filter: hue-rotate(-58deg) saturate(.62) brightness(1.03);
}
/* 流れ節の人物写真: 青被りを抜き、クリーム寄りに揃える */
.flow-card__media img {
  filter: saturate(.78) sepia(.07) contrast(.98);
}
```

`hue-rotate` は暫定策であり、**中期的には青の含まれない素材への差し替えが正解**（フィルタは肌色も動かすため、適用後に必ず目視確認すること）。

人の森モバイルの第一画面は白＋ブロブのみ。全幅の高彩度緑がその静けさを一撃で壊している。

### 7. 円マスク＋破線の装飾語彙を移植する（fold の3→4に効く）

人の森の識別子は「円形写真マスク」「破線のリーダー線」「有機的ブロブ」の3点セット。カタヅケは3点目しか採っていない。

写真本体を円マスクにするのは商品の視認性を落とすので**推奨しない**。円は装飾として添えるに留める。

## 人の森に寄せすぎてカタヅケ側の機能・可読性を損ねている点（4件）

1. **低コントラストのオリーブ系テキストが WCAG AA を割っている疑いが濃い。**
   `v_home_final` の注記「※ 最終的な買取額は業者の現物査定により決まります。」、`v_home_cats` の各タイル副題（冷蔵庫・洗濯機ほか 等）、グローバルナビのリンクは、いずれも白／淡セージ地に淡いオリーブグレーで置かれており、12〜13px の明朝細字と組み合わさって本文コントラスト比 4.5:1 を満たしていない可能性が高い。**特に注記は景表法・特商法まわりの打消し表示にあたるため、視認性不足は法務リスクでもある。**
   → 対処: 12px 未満を禁止、注記の色を `#5A6B50` 以上の暗さに、注記のみゴシック（`--font-sans`）に切り替える。

2. **本文の明朝細字＋長い行長で、スマホの可読性が落ちている。**
   `m_home` のリード文は明朝で1行あたり約22文字、行間が広く、細いウエイトのまま。人の森は「読ませない前提の詩的コピー」なので細明朝で成立するが、カタヅケのリードは**サービス理解に必須の実務情報**であり同じ扱いにはできない。
   → 対処: 本文は `font-family: var(--font-sans)`、`font-size: 15px`、`line-height: 1.85`。明朝は見出しと引用だけに限定する。

3. **蛍光ペン風マーカーが文中に分散し、可読性と信頼感の両方を削っている。**
   `v_home_fold` の「動けない」「買取総額」、`v_home_bundle` の「家まるごと」「まとめ全体の金額」「入札」、`v_home_fee` の「無料」×4。1画面に3〜4箇所の下線ハイライトが入ると視線が跳ね、文が断片化する。人の森にはこの語彙が無いため**整合にも寄与していない**。
   → 対処: 1セクション1箇所に制限。`.marker { background-image: linear-gradient(transparent 68%, #DFEBCB 68%); }` とし、色は淡く。

4. **余白過多で1画面あたりの情報量が落ちている。**
   `v_home_cats` は 12タイル×約440px で画面のほぼ全高を消費して、伝えている情報は「12カテゴリ対応」の一点のみ。`v_home_fee` も同様に1画面1メッセージ。`d_examples` に至っては空白のみ。人の森はコーポレートサイトなので低密度で成立するが、**カタヅケはスクロール量がそのまま離脱率に効くサービスサイト**であり、同じ密度は採れない。
   → 対処: カテゴリは3行×4列を2行×6列の低背タイル（高さ 120px 程度）に圧縮、料金節は表を1画面に収める。

補足（機能面の指摘）:
- `d_login` の「無料ログイン」というマイクロコピーは意味が通らない（ログインは元々無料）。デザイン以前の文言バグ。
- `v_home_flow` `v_biz_reasons` のカード本文が枠内で切れている。`-webkit-line-clamp` を使うなら省略記号を出し、使わないならカード高を `align-items: stretch` で揃える。

## この完成条件を満たしても課題が解決しないケース

**「同一グループに見える」が成立しても、カタヅケの事業KPIが下がるケース。**

完成条件は「独立レビュアーが同一グループのサイトに見えると判定（3以上）」という**視覚的類似性の一点のみ**を測っており、カタヅケがサービスサイトとして負っている目的——LINE友だち追加率・出品完了率——を一切測定していない。人の森はコーポレートサイトであり、その視覚言語（低コントラストの細明朝、1画面1メッセージの低密度、抑制された色数、控えめなボタン）は「読ませずに佇まいを伝える」ために最適化されている。これをサービスサイトにそのまま移植すると、**整合スコアは上がりながら、CTAの視認性・スクロール効率・情報密度が同時に下がり、登録率が落ちる**。特に本レビューの修正案6（モバイル固定CTAバーの緑ベタを白基調に変更）は、整合を +1 する一方でCVRを二桁%下げうる典型例である。

したがって、本完成条件を通過しても「人の森グループのサイトに見える、しかし前より申し込みが減ったサイト」が成立しうる。**合格判定と同時に、LINE友だち追加率の前後比較（最低2週間、モバイル分離）をゲートに追加しない限り、この課題は解決したと言えない。**

副次的にもう一点: 本整合はカタヅケ側で人の森の見た目を**手作業で模倣**しているだけで、トークン（色・書体・角丸・余白スケール）が共有されていない。人の森側が次回リニューアルした時点で整合は一晩で崩れ、同じ作業をやり直すことになる。恒久解は共通デザイントークンの切り出しであり、スクリーンショット一致では代替できない。

## 残る修正案・上位3件

### 1. `r_examples` の約3,100px空白と描画枚数の不一致（唯一の「破損」残存項目）

件数表示と実描画枚数が食い違っており、CSS 案件ではなくデータ取得／レンダリング側の欠陥。前回の「.next 破損」説では説明がつかない（隔離環境で撮り直してなお1枚）。まず切り分けること:

```
- フィルタ「すべて」選択時の件数ソースと、グリッドに渡している配列の長さを同一値で出しているか
- カード側で画像 URL 欠落やキー重複により 2枚目以降が早期 return していないか
- グリッドの高さがカード数に依らず固定になっていないか（min-height / aspect-ratio の固定値）
```

見た目の応急処置としては空状態を明示する:

```css
.examples-grid { min-height: 0; }
.examples-grid:has(> :only-child) ~ .examples-note { margin-block-start: 48px; }
.examples-section { padding-block: clamp(48px, 6vw, 96px); }
```

ただし**これは空白を詰めるだけで、件数不一致という不具合そのものは残る**。合格には実データでの複数枚描画が必要。

### 2. `r_signup` の巨大ピルLINEボタンの面積を落とす（2 → 3 に効く）

LINE緑の据え置き・公式ボタンのピル形状は受理する。**変えるべきは色でも角丸でもなく面積**。現状は幅約560px・高さ約60pxで画面最大の要素になっている。

```css
.signup-card .btn-line-auth {
  max-width: 360px;          /* 560px → 360px。公式規約の形状・色は維持 */
  margin-inline: auto;
  height: 52px;
}
/* 人の森の版面へ寄せる: 全面グレーグリーン地 → 白地＋淡ブロブ */
.signup-page { background: #FFFFFF; }
.signup-page::before {
  content: ""; position: absolute; inset: -18% auto auto -12%;
  width: 58vw; aspect-ratio: 1; border-radius: 50%;
  background: #EEF3E6; z-index: 0; pointer-events: none;
}
.signup-card { position: relative; z-index: 1; }
```

同じ処方が `r_login` にも当たる（`.login-page` / `.login-card`）。**2画面を同時に 2 → 3 に引き上げられる、費用対効果が最大の修正。**

### 3. 青の残存が1画面増えた件（`r_examples` のカード内商品写真）

前回指摘した flow・bundle に加え、今回 examples のカード内グリッドにも青（ノートPC・腕時計の文字盤・絵画）が入った。素材再生成が対象外である以上、当面はカード内の写真だけでもトーンを揃える:

```css
.example-card__thumb img { filter: saturate(.82) sepia(.05); }
```

**素材差し替えを先送りするほど、青の混入箇所は画面追加のたびに増える。**カテゴリ写真の選定基準（青を避ける／彩度上限）を素材ガイドラインとして先に文書化しておくべきで、これを怠ると同じ指摘が毎回再発する。
